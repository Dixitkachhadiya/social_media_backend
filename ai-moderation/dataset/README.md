# Multilingual vulgar content dataset

`multilingual_vulgar_content_dataset.xlsx` is generated by `generate_dataset.py` (seed `20261031`) from the
vocabulary and templates in `templates.py`.

**Every row is synthetic.** `source_type` is `synthetic: template`, `synthetic: word list` or
`synthetic: handwritten`. Rows were written for this project: no real people, usernames or private data. Hate
examples only refer to generic groups ("that community", "outsiders").

> This dataset is **not sufficient for reliable real-world moderation**. It is a starting point to build and test
> the pipeline. Hindi and Gujarati slang, spellings and severities were not reviewed by native speakers.

contrastive pairs: the same sentence with and without the abuse. They are not used to rewrite users' posts.

## Columns

| Column | Meaning |
|---|---|
| `id` | `S<sheet>-<n>` |
| `text` | The example |
| `language` / `language_code` | e.g. `Gujarati (romanized)` / `gu-Latn` |
| `script` | `Latin`, `Devanagari`, `Gujarati`, `Mixed` |
| `category` | `Clean`, `Mild profanity`, `Vulgar language`, `Personal abuse`, `Harassment`, `Hate speech`, `Threatening language` |
| `severity` | `none`, `low`, `medium`, `high` |
| `is_toxic` | Must be `False` exactly when `category = Clean` (training stops otherwise) |
| `target_type` | `none`, `individual`, `group` |
| `explanation` | Why the row has its label |
| `source_type` | How the row was produced (always synthetic in this version) |
| `flagged_terms` | Listed abusive terms found in the text (computed with the same matcher the service uses) |
| `clean_counterpart` | Same text without the abuse (training only) |
| `context_dependent` | Word with an ordinary meaning (dog, owl, brother-in-law); abusive only when aimed at someone |
| `obfuscation` | `none`, `variant`, `leet`, `spaced`, `repeated`, `star` |
| `template_group` | Rows from one template share a group; the split keeps each group in a single split |

## Labelling guide

| Category | Use when | Not this |
|---|---|---|
| Clean | Everyday talk, jokes, idioms ("traffic is killing me"), harsh criticism of things or ideas ("this policy is stupid", "ye movie bakwas thi") | – |
| Mild profanity | Mild swear words, not aimed at anyone ("damn", "crap", "saala") | aimed at a person → Personal abuse |
| Vulgar language | Strong or sexual profanity not aimed at anyone ("this fucking traffic", "bhenchod, wifi gaya") | aimed at a person → Personal abuse |
| Personal abuse | Insulting or demeaning a specific person ("tu sav nalayak che") | criticism of their work → Clean |
| Harassment | Targeted degradation, sexual/ableist slurs, exclusion campaigns, urging self-harm | a one-off insult → Personal abuse |
| Hate speech | Dehumanizing or excluding a group | criticizing a policy → Clean |
| Threatening language | Threats of violence or intimidation ("maar dunga", "watch your back") | violent idioms → Clean |

## Reviewing and extending

1. **Review first.** Have native speakers check sheets 2–7, especially slang spellings and severities. Fix labels
   in place. `is_toxic` must stay consistent with `category`.
2. **Add real examples carefully.** Collect only with permission and remove names, @handles, phone numbers and other
   personal data. Set `source_type` to e.g. `reviewed: real` and give each new example (and its variations) a new
   `template_group`.
3. **Add new slang to the word lists** (word-list rows: `source_type = synthetic: word list`, or your own
   `reviewed: word list`; update `training/data.py` if you use a new source type). Listed words are highlighted and
   always blocked, even in very short texts.
4. **Regenerating overwrites the workbook.** `python dataset/generate_dataset.py` rebuilds it from `templates.py`.
   Keep reviewed rows in a separate workbook and merge them, or extend the generator to load them.
5. **Retrain and compare:** `python training/train_baseline.py`, `python training/train_transformer.py`, then
   `python evaluation/evaluate.py`. Compare `evaluation/report.md` with the previous one before deploying.
