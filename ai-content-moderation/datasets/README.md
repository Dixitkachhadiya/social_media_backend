# Multilingual content moderation dataset

`multilingual_content_moderation_dataset.xlsx` is generated by `scripts/generate_dataset.py`
(seed `20261031`). **Every row is synthetic** (`synthetic = True`): written from templates for this
project, with no real people, usernames or private information. Hate examples only refer to generic
groups ("that community", "outsiders") and never to real individuals.

## Size (current version)

2,067 rows: 1,092 inappropriate and 975 clean.

| Sheet | Rows | Contents |
|---|---|---|
| Vulgar Words | 518 | Words/phrases with variants, leet/spaced/repeated forms, plus 10 clean look-alikes (*class*, *Gandhinagar*, *chhod do*, *kutro*…) |
| Vulgar Sentences | 545 | Sentences and short paragraphs with a `safe_rewritten_text` for each |
| Clean Content | 921 | Criticism, disagreement, jokes, idioms ("traffic is killing me"), compliments, everyday posts, paragraphs |
| Mixed Language | 83 | English + Hindi/Gujarati (Latin and native scripts) |
| Statistics | – | Counts per sheet, language, category, severity and obfuscation |

By language: English 672, Hindi (romanized) 418, Gujarati (romanized) 301, Hindi (Devanagari) 212,
Hinglish 188, Gujarati (script) 175, mixed 101.
By category: clean 975, insult 532, profanity 170, threat 170, harassment 118, hate 102.

Training also uses each `safe_rewritten_text` as a clean example (in the same template group), which gives
the model contrastive pairs: the same sentence with and without abuse.

## Limitations (read before use)

- **It does not represent real-world language.** Template generation repeats sentence structures; real
  posts are longer, messier, sarcastic and context-dependent.
- **Hindi and Gujarati slang, spellings and severities need review by native speakers.** They were written
  for this project without such review. Regional variation is barely covered.
- Hate speech and harassment are represented by a few generic patterns. Coded language, dog whistles and
  implicit threats ("you'll be in the hospital") are largely missing.
- Severity labels follow this project's policy (see the backend API documentation), not a universal standard.
- Good scores on this dataset do **not** guarantee good real-world accuracy.

## Columns

| Column | Meaning |
|---|---|
| `id` | Row id (W-, S-, C-, M- prefix by sheet) |
| `text` | The example |
| `language`, `language_code`, `script` | e.g. `Hindi (romanized)`, `hi-Latn`, `Latin` |
| `transliteration` | Romanized form (Vulgar Words) |
| `category` | `clean`, `profanity`, `insult`, `harassment`, `threat`, `hate` |
| `severity` | `none`, `low`, `medium`, `high` |
| `is_inappropriate` | Must be `False` exactly when `category = clean` (training checks this) |
| `context_dependent` | Word with an ordinary meaning (dog, owl, brother-in-law); only abusive when aimed at someone |
| `safe_replacement` / `safe_rewritten_text` | Respectful alternative (empty when no word swap can fix it, e.g. threats) |
| `explanation` | Why the row has its label |
| `template_group` | Rows generated from the same template share a group; the split keeps a group in one split |
| `obfuscation` | `none`, `variant`, `leet`, `spaced`, `repeated`, `star` |
| `synthetic` | `True` for generated rows; set `False` for reviewed real examples |

## Labelling guide

| Category | Use when | Example | Not this |
|---|---|---|---|
| `clean` | No abuse; includes harsh criticism of things/ideas, disagreement, frustration, idioms | "This policy is stupid", "Ye movie bakwas thi" | – |
| `profanity` | Vulgar words not aimed at a person | "damn, missed the bus" | profanity *at someone* → `insult` |
| `insult` | Demeaning a specific person | "Tu ekdum nalayak che" | criticism of their *work* → `clean` |
| `harassment` | Targeted degradation, sexual/ableist slurs, exclusion campaigns, urging self-harm | "nobody wants you here", "kys" | one-off insult → `insult` |
| `threat` | Threat of violence or harm, explicit or intimidating | "maar dunga tujhe", "watch your back" | violent idioms ("killing it") → `clean` |
| `hate` | Dehumanizing or excluding a group | "those people are vermin" | criticizing a policy → `clean` |

## Adding reviewed examples

1. Collect real examples only with permission, and remove names, @handles, phone numbers and other personal data.
2. Add them to the right sheet with `synthetic = False` and a new `template_group` (reuse a group only for
   variations of the same sentence).
3. Have a second reviewer check labels; for Hindi/Gujarati, use native speakers.
4. Retrain (`python training/train.py`) and compare the new evaluation report with the previous one.
   Keep `scripts/generate_dataset.py` for the synthetic part, but note that re-running it **overwrites the
   workbook**: keep reviewed rows in a separate copy and merge them back, or extend the generator to load them.
